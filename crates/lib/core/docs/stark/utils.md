| bit_reverse_len_parallel | Reverse the lowest `bits` bits of `index` using parallel bit-swap.<br />`pow2_shift` must equal 2^(32 - bits); the caller pre-computes it once.<br /><br />The algorithm has two parts:<br /><br />1) Left-shift: multiply index by pow2_shift = 2^(32-bits) to place the `bits`<br />meaningful bits into the top of a 32-bit word. Since index < 2^bits, the<br />product is always < 2^32 so u32wrapping_mul is exact.<br /><br />2) Full 32-bit reversal via 5 parallel swap steps. Each step k (for k=1,2,4,8,16)<br />swaps every adjacent group of k bits. A mask isolates the even-positioned<br />groups; the odd-positioned groups are the complement. Shifting each half by<br />k positions and combining swaps all groups simultaneously. After all 5 steps,<br />bit position i has moved to position 31-i, which (because of the initial<br />left-shift) is exactly position (bits-1-i) of the original -- i.e., the<br />reversed index. No final shift is needed.<br /><br />The two halves never overlap, so XOR = OR = ADD; we use XOR (1 cycle vs 3 for<br />u32wrapping_add).<br /><br />Input: [index, pow2_shift, ...]<br />Output: [rev_index, ...]<br />Cycles: 78<br /> |

| derive_order_tag_from_heights | Derives the Lehmer proof-order tag of the height-sorted proof order over any AIR count.<br /><br />The proof order sorts the relation's AIRs by ascending log height, with the canonical<br />instance order breaking ties (a stable sort). For each canonical AIR k with log<br />height h_k read from `heights_ptr + k`:<br /><br />inv_k   = #{m < k : h_m > h_k}<br />after_k = #{m > k : h_m < h_k}<br />pos_k   = k - inv_k + after_k<br />tag    += inv_k * (num_airs - 1 - pos_k)!<br /><br />The comparisons are branch-free (flag products); the loops are `while`-based so this procedure<br />can serve any relation (repeat bounds would need compile-time counts). PVM uses this generic<br />path. The VM retains a fixed-count specialization with compile-time repeat bounds; tests pin<br />both implementations to the shared Rust `order_tag` convention.<br /><br />Preconditions (`num_airs` is the caller's contract): `num_airs <= 12`, or the tag<br />overflows u32 and the ranking collides once `factorial` wraps the field; `num_airs`<br />must be a small honest count (it is relation metadata, never prover data). The four<br />u32 comparisons in each inner iteration reject a height outside the u32 range.<br /><br />Input:  [num_airs, heights_ptr]<br />Output: [tag]<br /> |
