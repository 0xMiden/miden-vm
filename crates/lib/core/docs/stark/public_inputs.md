
## miden::core::stark::public_inputs
| Procedure | Description |
| ----------- | ------------- |
| process_public_inputs | Processes the public inputs.<br /><br />This generic procedure dispatches to the relation-specific public-input handler via `dynexec`.<br />The relation handler owns its public-input schema and Fiat-Shamir observation schedule.<br /><br />Inputs:  [...]<br />Outputs: [...]<br /><br />Invocation: exec<br /> |
| compute_and_store_public_inputs_address | Computes and stores the start address of the ACE public-input region.<br /><br />The public-input region stores `num_fixed_len_pi` base-field public values as extension-field<br />slots, i.e. two base-field memory cells per public value. It is placed immediately before the<br />aux-randomness word in ACE READ.<br /><br />This helper only computes the ACE READ public-input pointer. Relation-specific code owns any<br />additional statement inputs that are not read by the ACE circuit.<br /><br />Inputs:  [aux_rand_ptr, num_fixed_len_pi, ...]<br />Outputs: [...]<br /><br />Invocation: exec<br /> |
| load_base_store_extension_double_word_from_mem | Loads 8 base-field elements from memory, stores them as 8 extension-field elements, and leaves<br />the base elements in the block slots for one complete Eidos compression.<br /><br />Transcript absorption is handled separately (see `sys/vm/public_inputs::absorb_public_inputs`),<br />so callers may treat the returned `A0`/`A1` words as disposable placeholders.<br /><br />Inputs:  [BLOCK_LO, BLOCK_HI, CV, ptr, ...]<br />Outputs: [A0, A1, CV, ptr + 16, ..]<br /><br />where A0 and A1 are the original base element words (from advice).<br /><br />Invocation: exec<br /> |
