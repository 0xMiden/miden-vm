
## miden::core::stark::security
| Procedure | Description |
| ----------- | ------------- |
| compute_conjectured_security_level | Computes a proof's conjectured security level, in bits, from the security descriptor returned<br />by the verifier which authenticated it.<br /><br />The round-budget arithmetic is common to the MVM and PVM. Expensive logarithms of fixed AIR<br />shape values are evaluated natively and returned as four fixed-point round bases. This<br />keeps the in-VM estimator small while leaving it independent of either relation:<br /><br />- `lookup_base_fp = log2(\|E\|) - ceil(log2((max_message_width + 2) * fractions_per_row))`<br />- `composition_base_fp = log2(\|E\|) - ceil(log2(num_composed_constraints))`<br />- `ood_base_fp = log2(\|E\|) - ceil(log2(max_constraint_degree + 1))`<br />- `deep_base_fp = log2(\|E\|) - ceil(log2(num_deep_terms))`<br /><br />All values above are in Q16 fixed point with conservative rounding. Computing their logarithms<br />in MASM would be needlessly expensive: they are fixed by the verified relation, derived by the<br />native AIR security module, and guarded against drift there.<br /><br />This procedure is intentionally not a general-purpose estimator. Its input must be the<br />descriptor returned by a successful MVM or PVM recursive verifier. Their exact accepted<br />envelopes are:<br /><br />- Shared proof parameters: `num_queries` in `7..=150`; query, DEEP, and folding grinding in<br />`0..=31` bits.<br />- MVM: lookup grinding 0, maximum log trace height in `6..=29`, 28 lookup fractions per row,<br />and `3..=258` one-time boundary terms (three fixed terms plus 0..=255 kernel procedures).<br />- PVM: lookup grinding 0, maximum log trace height in `16..=29`, 247 lookup fractions per row,<br />and eight fixed one-time boundary terms.<br /><br />The verifiers validate the variable fields and supply the normalized relation constants.<br />Within these envelopes, all fixed-point arithmetic below fits in a u32 and matches the native<br />estimator exactly. Changing a verifier envelope requires reviewing that arithmetic guarantee.<br />This procedure does not authenticate a descriptor: callers must pass the verifier's twelve<br />returned values without modification. Supplying caller-assembled values is programmer error.<br />No descriptor field controls a loop or allocation, so cycle and stack use are constant.<br /><br />`num_lookup_boundary_terms` is deliberately relation-neutral. The MVM derives it from the<br />authenticated kernel witness plus its fixed core terms; the PVM returns the fixed-environment<br />boundary count. The common correction below does not know how either value was derived.<br /><br />The challenge field, commitment collision cap, blowup, and folding arity are fixed by the shared<br />recursive PCS and are encoded by the constants above. This procedure applies no acceptance<br />policy; the caller compares the returned level with its own threshold.<br /><br />Inputs:  [num_queries, query_pow_bits, lookup_pow_bits, deep_pow_bits, folding_pow_bits,<br />log_max_height, lookup_base_fp, composition_base_fp, ood_base_fp, deep_base_fp,<br />lookup_fractions_per_row, num_lookup_boundary_terms, ...]<br />Outputs: [level, ...]<br /><br />Invocation: exec<br /> |
