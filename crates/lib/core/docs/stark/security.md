
## miden::core::stark::security
| Procedure | Description |
| ----------- | ------------- |
| compute_conjectured_security_level | Computes a proof's conjectured security level from the descriptor returned by the MVM or PVM<br />recursive verifier:<br /><br />level = min(query, lookup, deep).<br /><br />The native report also includes constraint composition, out-of-domain evaluation, FRI folding,<br />and the field/hash cap. The bounds checked here keep those four terms above lookup. Lifted STARK<br />applies grinding before DEEP, FRI folding, and query sampling. Lookup grinding must be zero.<br /><br /># Query term<br /><br />query = floor(num_queries * BITS_PER_QUERY_FP / 2^16) + query_pow_bits.<br /><br />This is the native fixed-point query calculation, using the full extension-field cardinality.<br /><br /># Lookup term<br /><br />Let A = (max_message_width + 2) * fractions_per_row, q = ceil(log2(A)), and<br />R = r_w * FP_ONE + r_f be the Q16 correction for boundary fractions. Define<br /><br />s = q * FP_ONE - ceil(FP_ONE * log2(A)).<br /><br />Since the sampling support has exactly 126 bits, the whole-bit lookup bound is<br /><br />lookup = 126 - q - height - r_w - borrow,<br />borrow = 1 if s < r_f, otherwise 0.<br /><br />To avoid a fixed-point logarithm, set P = 2^q and g = P - A. The positive power series<br />-log2(1 - x) = log2(e) * (x + x^2/2 + ...) gives the integer lower bound<br /><br />t1 = floor(LOG2_E_FP * g / P),<br />b = t1 + floor(t1 * g / (2 * P)) <= s.<br /><br />The procedure subtracts one when b < r_f. Because b <= s, it cannot overstate the native<br />bound and can understate it by at most one bit. For MVM, A = (16 + 2) * 73 = 1314 gives<br />b = 39958, while R is at most 5222 (258 fixed/kernel boundary fractions at height 6). For PVM,<br />A = (18 + 2) * 215 = 4300 gives b = 55590 and R <= 131 (19 boundary fractions at height 6).<br />Thus b >= r_f for both deployed shapes throughout the accepted height range.<br /><br />The accepted coefficient range is 257..=65536. Each factor is also limited to 65536 so their<br />product cannot wrap. At widths 16 and 18, the upper bound permits 3640 and 3276 fractions per<br />row respectively. The descriptor supplies these values from the verified AIR shape.<br /><br /># DEEP term<br /><br />Let `n = num_deep_terms` and `q = ceil(log2(n))`. The native round subtracts<br />`ceil(log2(n) * FP_ONE)` and the LDE height `height + 3` from the Q16 challenge-support size,<br />then adds `deep_pow_bits`. The Eidos support has exactly 126 bits, so its whole-bit value is<br /><br />deep = min(126, 123 - q - height + deep_pow_bits).<br /><br /># Why the other four terms can be omitted<br /><br />A >= 257, height >= 6, and R >= 0 give<br /><br />lookup <= floor(126 - log2(257) - height) = 117 - height <= 111.<br /><br />Each omitted term has a larger lower bound:<br /><br />- out-of-domain: log_blowup = 3 permits at most eight quotient chunks, and both verifiers reject<br />AIRs of degree greater than nine. With local and next openings, the DEEP-ALI identity degree<br />is at most max(9 * (H + 1) + H - 1, 9 * H + 1) <= 11 * H for H = 2^height >= 64.<br />OOD sampling rejects zero and points in the trace subgroup or LDE coset. These are base-field<br />points; conditioning on acceptance costs at most one Q16 unit in the native bound. Since<br />ceil(FP_ONE * log2(11)) + 1 < 4 * FP_ONE, the term still exceeds 122 - height;<br />- FRI folding: FRI_FOLDING_BASE_BITS - height + folding_pow >= 120 - height;<br />- composition: composed <= 8192 gives at least 126 - log2(8192) = 113 bits;<br />- collision cap: SECURITY_CAP_BITS = 126 > 111.<br /><br />The OOD and folding bounds subtract the same height as lookup. Thus their margins hold at<br />every accepted height. Folding grinding can only increase its bound. The cap is also greater<br />than lookup, so omitting a query clamp cannot affect the final minimum.<br /><br /># Contract<br /><br />The input must be the unmodified descriptor returned by a successful MVM or PVM recursive<br />verifier. This is not a general-purpose estimator for caller-assembled parameters.<br /><br />Every descriptor field is checked against the estimator envelope before it is used or discarded.<br />The lower bounds on height and the lookup coefficient support the proof that the other terms<br />cannot determine the result.<br />The upper bounds on height, coefficient, and boundary terms keep the arithmetic in range, and<br />the explicit `base >= 1` check validates the lookup subtraction after applying the correction.<br />Requiring zero lookup grinding keeps the native cap irrelevant to the lookup term. The procedure<br />traps for descriptors outside this envelope instead of returning a security level.<br /><br />The procedure is loop-free and has bounded execution cost for every accepted descriptor.<br /><br />`num_lookup_boundary_terms` counts boundary fractions in addition to the per-row fractions.<br />Each fraction contributes `(max_message_width + 2) / \|S\|`, where `S` is the lookup challenge's<br />sampling support. The caller compares the returned security level with the threshold required<br />by its application.<br /><br />Inputs:  [lookup_pow_bits, num_composed_constraints, max_constraint_degree, num_deep_terms,<br />max_message_width, num_lookup_boundary_terms, lookup_fractions_per_row,<br />log_max_height, num_queries, query_pow_bits, deep_pow_bits, folding_pow_bits, ...]<br />Outputs: [level, ...]<br /><br />Invocation: exec<br /> |
| compute_proven_security_level | Computes the proven security level: the better of the unique-decoding (UDR) and<br />list-decoding (LDR) bounds for the descriptor returned by a successful MVM or PVM recursive<br />verifier. It assumes log blowup 3, log folding arity 2, final degree log 7, two OOD points,<br />and a 125-bit challenge support, as in the native proven report.<br /><br />The conjectured procedure validates the descriptor and supplies a cap K on both regimes.<br />Within the envelope K is below the UDR composition, OOD, and folding terms, so UDR needs only<br />its query and batching terms; reaching K or that batching bound skips LDR. LDR evaluates<br />every round. Its composition, OOD, and lookup terms pay the list size `L+=(2m+1)*sqrt(2)`.<br /><br />LDR queries increase with m and every other term decreases. If M=min(1000,H/2) is<br />query-bound it attains the LDR optimum; otherwise fixed probes bracket the crossing and a<br />binary search over whole-bit levels finds the best integer m. Rounding is conservative, and<br />for deployed shapes the result is at most one bit below native.<br /><br />Unsupported descriptors trap. Caller stack values and memory are preserved.<br /><br />Inputs: [lookup_pow_bits, num_composed_constraints, max_constraint_degree, num_deep_terms,<br />max_message_width, num_lookup_boundary_terms, lookup_fractions_per_row,<br />log_max_height, num_queries, query_pow_bits, deep_pow_bits, folding_pow_bits, ...]<br />Outputs: [level, ...]<br />Invocation: exec<br /> |
