
## miden::core::stark::constraints_eval_inputs
| Procedure | Description |
| ----------- | ------------- |
| set_up_auxiliary_inputs_ace | Sets up the multi-AIR ACE input layout shared by relation verifiers.<br /><br />The stark-vars block starts with 10 EF slots:<br /><br />Word 0 (slots 0-1): alpha, z^N<br />Word 1 (slots 2-3): z_k, is_first<br />Word 2 (slots 4-5): is_last, is_transition<br />Word 3 (slots 6-7): reserved, weight0<br />Word 4 (slots 8-9): f, s0<br /><br />The multi-AIR layout then appends:<br />slot 10: multi-air fold beta (sampled by the generic random coin). Staged for every relation,<br />but the canonical circuit folds with the per-AIR MultiAirFoldCoeff slots below<br />instead of this challenge directly; it stays a READ slot because AIR k's selector<br />triple is pinned at FIRST_SELECTOR_OFFSET + SELECTOR_STRIDE * k, and removing it<br />would shift every selector offset and re-mint both relation digests.<br />slots 11 + 3k .. 13 + 3k: AIR k's lifted selectors, canonical instance order<br /><br />`heights_ptr` addresses the relation's `num_airs` consecutive per-AIR log-height<br />cells; AIR k's selectors are derived from the height at `heights_ptr + k`.<br /><br />`stark_vars_ptr` is the relation's stark-vars base. The ACE READ section is one dense<br />vector whose region spacing must equal the relation's circuit layout spacing, so this<br />base is relation-local rather than a shared constant.<br /><br />The three quotient recomposition inputs are relation-supplied, and they do NOT all<br />derive from the same quantity:<br />`quot_shift_ratio` (f)  the primitive D-th root of unity, D = the quotient arity<br />`quot_first_weight`     1 / (D * s0^(D-1)) — a function of BOTH D and s0<br />`quot_first_shift` (s0) shift^N — a PCS-configuration value (LDE shift and blowup),<br />independent of D<br />When a relation's arity and blowup factor coincide, a value derived from either quantity<br />is numerically identical; a relation whose arity differs from its blowup needs different<br />values, which is why these cannot stay shared constants.<br /><br />Input:  [max_cycle_len_log, num_airs, heights_ptr, stark_vars_ptr, quot_first_weight,<br />quot_first_shift, quot_shift_ratio, ...]<br />Output: [...]<br /> |
| stage_air_fold_coefficients | Stages each AIR's multi-air fold coefficient in the ACE input region.<br /><br />AIR `k`'s coefficient is `beta^(num_airs - 1 - pos_k)`, where `pos_k` is that AIR's position in<br />the height-sorted proof order. The fold is a Horner accumulation over proof order, so the AIR<br />opened last carries `beta^0` and the AIR opened first carries `beta^(num_airs - 1)`. Keying the<br />exponent by proof position rather than by instance index is what makes the staged block<br />order-invariant; the two agree only for the identity order.<br /><br />`beta` is the same multi-air fold challenge `set_up_auxiliary_inputs_ace` stages at<br />MULTI_AIR_FOLD_BETA_OFFSET.<br /><br />Coefficient `k` lands at base offset `FIRST_SELECTOR_OFFSET + SELECTOR_STRIDE * num_airs + 2k`,<br />immediately after the selector block. That base is derived from `num_airs` rather than passed<br />in: this module is shared by every relation verifier, so a separate input would be a second<br />encoding of a value it must already equal.<br /><br />Precondition: `num_airs >= 2`. Counts above `MAX_ORDER_AIRS` trap on the first AIR, in<br />`utils::proof_order_position_from_heights`.<br /><br />Input:  [num_airs, heights_ptr, stark_vars_ptr, ...]<br />Output: [...]<br /> |
