Eidos/u32-XOR AEAD helpers.<br /><br />The encryption path uses `crypto_stream`, which calls the AEAD stream chip to<br />derive Eidos XOF blocks from `K_CTR` and a counter. The chip XORs the stream<br />with plaintext felts and writes expanded ciphertext limbs.<br />Authentication covers expanded ciphertext with empty associated data.<br />The MAC pairs adjacent Felts as quadratic-extension coefficients and begins Horner evaluation<br />at one, binding the number of coefficients.<br /><br />Security contract:<br />- callers must never reuse `(key, nonce)`;<br />- counter blocks under a fixed `K_CTR` must be unique;<br />- expanded-ciphertext authentication is the canonical AEAD tag direction;<br />- this construction is not nonce-misuse-resistant.<br /><br />Test vectors are checked against `miden_crypto::aead::aead_eidos::expanded`.<br />
