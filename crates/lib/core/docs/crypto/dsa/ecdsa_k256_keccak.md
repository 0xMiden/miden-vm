
## miden::core::crypto::dsa::ecdsa_k256_keccak
| Procedure | Description |
| ----------- | ------------- |
| verify | Verifies a secp256k1 ECDSA witness using the `miden-crypto::ecdsa_k256_keccak` message,<br />public-key commitment, and signature-scalar conventions, encoded in the native limb ABI below.<br />Acceptance intentionally differs from the Rust verifier: high-s witnesses are accepted.<br /><br />Inputs:<br />Operand stack: [PK_COMM, MSG_WORD, ...]<br />Advice stack:  [QX[8] \| QY[8] \| SIG_R[8] \| SIG_S[8] \| ...]<br />Outputs:<br />Operand stack: [...]<br />Advice stack:  [...]<br /><br />Where:<br />- `PK_COMM`: Poseidon2 hash commitment of `QX[8] \|\| QY[8]`, where coordinates are native<br />little-endian numeric u32 limbs, one limb per Felt.<br />- `MSG_WORD`: single word / 4 felts representing the 32-byte message to verify.<br />- `QX[8]`, `QY[8]`: native public-key coordinates as little-endian u32 limbs.<br />- `SIG_R[8]`, `SIG_S[8]`: native signature scalars as little-endian u32 limbs.<br /><br />Local memory layout (element addresses):<br />- loc[0 ..16] : native public key, QX[8] \|\| QY[8].<br />- loc[16..24] : Keccak256 message/digest scratch buffer.<br /><br />No result word is pushed. The procedure traps on malformed native limbs, invalid/off-curve public<br />keys, invalid signature scalars, or failed signature verification.<br /><br />Low-s is intentionally not enforced: this procedure proves that some untrusted advice satisfies<br />the ECDSA equation, and `(r, s)` and `(r, n - s)` are equivalent witnesses. An adaptation that<br />verifies a committed or canonical Ethereum signature must bind the exact signature encoding inside<br />the VM and enforce low-s on that bound value.<br /><br />Advice is untrusted. This procedure binds QX/QY to `PK_COMM`, and validates the public key,<br />reduced Keccak prehash, and signature scalars through precompile-backed deferred evaluation.<br /><br />Invocation: exec<br /> |
| verify_bytes | Verifies a secp256k1 ECDSA witness over a variable-length message stored as bytes in memory.<br /><br />Inputs:<br />Operand stack: [PK_COMM, MSG_PTR, MSG_LEN_BYTES, ...]<br />Advice stack:  [QX[8] \| QY[8] \| SIG_R[8] \| SIG_S[8] \| ...]<br />Outputs:<br />Operand stack: [...]<br />Advice stack:  [...]<br /><br />Where:<br />- `PK_COMM`: Poseidon2 hash commitment of `QX[8] \|\| QY[8]`, where coordinates are native<br />little-endian numeric u32 limbs, one limb per Felt.<br />- `MSG_PTR`: word-aligned address containing the message as packed little-endian u32 limbs.<br />- `MSG_LEN_BYTES`: number of message bytes to hash. Unused bytes in the final u32 and remaining felts<br />in the final 32-byte chunk must be zero.<br />- `QX[8]`, `QY[8]`: native public-key coordinates as little-endian u32 limbs.<br />- `SIG_R[8]`, `SIG_S[8]`: native signature scalars as little-endian u32 limbs.<br /><br />No result word is pushed. The procedure traps if:<br />- `MSG_PTR` is not word-aligned.<br />- `MSG_LEN_BYTES` exceeds the configured `max_hash_len_bytes` execution limit.<br />- a message-memory felt is not a valid u32.<br />- unused message bytes or felts in the final 32-byte chunk are nonzero.<br />- public-key or signature limbs are malformed, the public key is invalid/off-curve, the signature<br />scalars are invalid, or signature verification fails.<br /><br />Advice is untrusted. This procedure binds QX/QY to `PK_COMM`, hashes the specified memory range,<br />and validates the reduced Keccak prehash and signature scalars through precompile-backed deferred<br />evaluation.<br /><br />Invocation: exec<br /> |
| ecrecover | Recovers an Ethereum address from a secp256k1 signature and message hash.<br /><br />Input:  [INPUT_PTR, ...]<br />Output: [ADDRESS_U32[8], ...]<br /><br />`INPUT_PTR` must be word-aligned and point to the standard 128-byte ECRECOVER input, packed into<br />little-endian u32 memory elements:<br /><br />HASH[32] \|\| V[32] \|\| R[32] \|\| S[32]<br /><br />The four fields use Ethereum's big-endian encoding. `V` must encode 27 or 28, and `R` and `S`<br />must be nonzero canonical secp256k1 scalars. High-s signatures are accepted.<br /><br />The result is the packed little-endian u32 form of<br />`0[12] \|\| Keccak256(QX_BE \|\| QY_BE)[12..]`.<br /><br />Invalid input traps instead of returning the EVM precompile's empty failure output. The recovered<br />key is untrusted advice; deferred curve and Keccak checks bind it to the input and result.<br /><br />Invocation: exec<br /> |
