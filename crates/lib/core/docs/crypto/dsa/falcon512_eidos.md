
## miden::core::crypto::dsa::falcon512_eidos
| Procedure | Description |
| ----------- | ------------- |
| mod_12289 | Reduces a 64-bit dividend modulo M = 12289 using the `falcon_div` advice event.<br />The caller must ensure that both input limbs are u32; this procedure checks the<br />event's quotient and remainder. `verify` uses the VM divider directly.<br /><br />Input: [a_lo, a_hi, ...]<br />Output: [a mod M, ...]<br /> |
| hash_to_point_s1_norm_sq | Computes the squared norm of s1 = c - pi in Z_M[x]/(x^512 + 1), generating the hash-to-point<br />coefficients c from the message and nonce as they are needed.<br />Generated coefficients are consumed on the stack without being stored in memory.<br /><br />The word-aligned pi_ptr points to 1024 coefficients of the signed integer product pi = h * s2,<br />represented in the Miden field. Each product coefficient pi_i must satisfy<br />\|pi_i\| <= 512 * (M - 1) * M_HALF, since h_j is in [0, M) and centered s2_j is in<br />[-M_HALF, M_HALF]. The caller must establish these input ranges and the product identity;<br />`verify` uses `load_h_s2_and_product` to check the ranges and probabilistically check the<br />product identity.<br /><br />A fixed Eidos seed is derived from the eight-Felt nonce and the zero-padded message word.<br />Each counter from 0 through 127 occupies the first element of an otherwise zero block;<br />compressing that block under the seed emits four 63-bit samples in word order.<br />Direct modular reduction replaces rejection sampling as described on page 31 of<br />https://falcon-sign.info/falcon.pdf, with 63-bit samples here.<br /><br />For each i, the unreduced coefficient of s1 is c_i + pi_{i+512} - pi_i. Under the product<br />bound, adding J + M_HALF, where J = 512 * M^2, makes the product term positive and below 2J.<br />The reduction returns r = (s1_i + M_HALF) mod M in [0, M), so r - M_HALF is the centered<br />s1 coefficient in [-M_HALF, M_HALF] whose square contributes to the returned norm.<br />`verify` adds the squared norm of s2 and checks \|\|s1\|\|^2 + \|\|s2\|\|^2 < SQUARE_NORM_BOUND.<br /><br />Input: [pi_ptr, MSG(4), NONCE(8), ...]<br />Output: [norm_sq(s1), ...]<br /><br /> |
| load_h_s2_and_product | Loads the expanded public key h, shifted signature s2', and claimed product pi from<br />advice into consecutive memory regions starting at `ptr`. It checks that h hashes to<br />`public_key`, that h and s2' have coefficients in [0, M), and that pi = h * s2<br />at a Fiat-Shamir point in the quadratic extension of the Miden field.<br /><br />Here s2'_i = s2_i + M_HALF, with centered s2_i in [-M_HALF, M_HALF], and<br />pi is the product with centered s2. The evaluation point is supplied on advice<br />to permit evaluation while hashing; the procedure checks it against the digest<br />of the public-key commitment, s2', and pi. The identity check is probabilistic.<br />For a true polynomial product, each pi coefficient represents a signed convolution<br />value with absolute value at most 512 * (M - 1) * M_HALF.<br /><br />Inputs:<br />Operand stack: [ptr, PK, ...]<br />Advice stack:  [tau1, tau0, h_0, ..., h_511, s2'_0, ..., s2'_511, pi_0, ..., pi_1023, ...]<br />Outputs:<br />Operand stack: [...]<br />Advice stack:  [...]<br /><br /> |
| norm_sq | Returns the square of the centered representative of e in [0, M).<br /><br />We use the following formula to do so:<br />normalize(e) = e^2 - phi * (2*M*e - M^2) where phi := (e > (M - 1)/2)<br /><br />The formula implements:<br /><br />if e > (M-1)/2:<br />return (M - e)^2<br />else:<br />return e^2<br /><br />The use of the formula avoids using the if-else block.<br /><br />Input: [e, ...]<br />Output [norm(e)^2, ...]<br /><br />Cycles: 20<br /> |
| compute_s2_norm_sq | Compute the square norm of the polynomial s2 given a pointer to its coefficients.<br /><br />The coefficients are stored as s2'_i = s2_i + M_HALF in [0, M), as checked by<br />`load_h_s2_and_product`. The centered coefficient is s2'_i - M_HALF.<br /><br />Input: [s2_ptr, ...]<br />Output: [norm_sq(s2), ...]<br /><br /> |
| verify | Verifies a Falcon signature against the public-key commitment PK and message word MSG.<br />PK is the Eidos Falcon commitment returned by `PublicKey::to_commitment()`.<br />The signature advice supplies the expanded key, shifted signature, claimed product, and nonce.<br /><br />The procedure returns when the public key hash, Fiat-Shamir product check, and<br />signature norm bound pass. The product check is probabilistic.<br /><br />Inputs:<br />Operand stack: [PK, MSG, ...]<br />Advice stack:  [SIGNATURE]<br />Outputs:<br />Operand stack: [...]<br />Advice stack:  [...]<br /><br />SIGNATURE = [tau1, tau0, h(512), s2'(512), pi(1024), nonce(8)],<br />where:<br />- tau = (tau0, tau1) is an element in the quadratic field extension at which the product relation<br />between `h * s2 = pi` is checked.<br />- h_i are the coefficients of the expanded public key polynomial.<br />- s2'_i are the coefficients of the signature polynomial in the shifted representation<br />s2'_i = s2_i + M_HALF, where s2_i is the centered representative of the i-th coefficient<br />(see `load_h_s2_and_product`).<br />- pi_i are the coefficients of `h * s2` in Z_Q[x] where Q is the Miden VM prime and s2 is<br />centered.<br />- nonce_i are field elements representing the nonce associated to the signature.<br /><br /> |
| move_sig_from_map_to_adv_stack | Moves the signature from the advice map to the advice stack, where the signature is stored in<br />the hashmap at key `hash(PK \|\| MSG)`, where `hash()` is the VM-native hash. The signature is<br />expected to be stored in reverse order, so that it gets pushed on the advice stack in the<br />correct order.<br /><br />Inputs:<br />Operand stack: [PK, MSG, ...]<br />Advice stack:  []<br />Advice map: hash(PK \|\| MSG) -> SIGNATURE<br />Outputs:<br />Operand stack: [PK, MSG, ...]<br />Advice stack:  [SIGNATURE]<br /> |
