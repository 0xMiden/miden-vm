
## miden::core::sys::pvm
| Procedure | Description |
| ----------- | ------------- |
| load_air_context | Loads the fixed PVM relation context.<br /><br />Stores the ten AIR heights in `ChipletAir::all()` order, their maximum, the proof-order tag,<br />relation commitments, and fixed OOD/query-row addresses.<br /><br />Advice order: [h0, ..., h9].<br />Inputs:  [...]<br />Outputs: [...]<br /> |
| compute_conjectured_security_level | Computes the PVM proof's conjectured security level, in bits.<br /><br />Takes the minimum over the lookup challenge, constraint composition, out-of-domain evaluation,<br />DEEP composition, FRI folding, FRI query, and commitment-collision terms. The result is a<br />property of both the transcript-bound proof parameters and its maximum AIR trace height. This<br />procedure applies no acceptance policy; the caller compares the returned level with its own<br />threshold.<br /><br />Must match `miden_precompiles_air::security::security_report` bit-for-bit (enforced by<br />cross-tests). `log_max_height` comes from verifier-owned memory after `verify_proof`; the fixed<br />BytePairLut trace makes every valid PVM maximum at least FIXED_LOG_HEIGHT_3.<br /><br />PRECONDITION: `num_queries <= 150`, so the query product fits in a u32. Parameters returned by<br />`verify_proof` satisfy this bound because the generic verifier enforces it.<br /><br />Inputs:  [num_queries, query_pow_bits, deep_pow_bits, folding_pow_bits, log_max_height, ...]<br />Outputs: [level, ...]<br /><br />Invocation: exec<br /> |
| request_proof | Requests and stages a PVM proof package for the deferred root.<br /><br />This procedure does not authenticate the root or enforce call order. The caller must first<br />obtain `D` from a successful verifier or another trusted part of its own computation.<br /><br />The event exposes the PVM verifier root followed by `D` to the host. Async hosts may suspend<br />execution while they obtain the proof and return advice-map and Merkle-store mutations. Once the<br />host returns, this procedure fetches the proof stream by<br />`sys::build_proof_request_key(verifier_root, D)` and<br />stages it on the advice stack. The response remains untrusted until the caller invokes<br />`pvm::verify_proof` against the unchanged root.<br /><br />The core library deliberately provides no default handler because the host must supply the<br />deferred state or another witness source for `D`.<br /><br />Fails if the host has not populated the advice map under<br />`build_proof_request_key(verifier_root, D)` by the time its event handler returns.<br /><br />Inputs:  [D]<br />Outputs: [D]<br /><br />Invocation: exec<br /> |
| verify_proof | Verifies a lifted-STARK proof for the ten-chiplet PVM relation and returns the proof's<br />transcript-bound security parameters.<br /><br />The deferred root is the relation's four public base-field values. The caller supplies it as<br />the obligation being settled; all proof data and security/shape metadata are read from advice.<br />Successful verification authenticates the root at the returned security parameters. The generic<br />verifier enforces structural bounds and binds the supplied parameters into the Fiat-Shamir<br />transcript. This procedure applies no acceptance policy: the caller grades the returned<br />parameters under its own policy.<br /><br />Fails if the advice does not encode a supported PVM proof, or if any transcript, opening,<br />commitment, constraint, or public-root check fails.<br /><br />Inputs:  [D]<br />Outputs: [num_queries, query_pow_bits, deep_pow_bits, folding_pow_bits]<br /><br />Invocation: exec<br /> |
