
## miden::core::sys::pvm::public_inputs
| Procedure | Description |
| ----------- | ------------- |
| stage_public_root | Stores the deferred root as the PVM's four base-field public values.<br /><br />The ACE READ layout represents each base value as a quadratic-extension element, so the root<br />is stored as `[D0, 0, D1, 0, D2, 0, D3, 0]` at the generated public-input boundary. Every cell<br />is overwritten, including the zero coordinates, so sequential verification cannot read stale<br />relation state.<br /><br />Inputs:  [D0, D1, D2, D3, ...]<br />Outputs: [...]<br /> |
| process_public_inputs | Observes the PVM statement and instance shape (step I of the verifier).<br /><br />This mirrors the lifted verifier's exact order:<br /><br />1. default statement encoding `[4, D0, D1, D2, D3, 0, 0]`, where the final zeroes are<br />`max_aux_inputs` and `aux_inputs.len()`;<br />2. instance shape `[10, h0, ..., h9]` in `ChipletAir::all()` order.<br /><br />The trusted preprocessed commitment is already buffered by `random_coin::init_seed`; with this<br />18-felt statement-and-shape stream, the combined 22 felts perform two Eidos compressions and<br />leave six felts buffered. The generic verifier appends the main commitment and flushes before<br />sampling, exactly matching the Rust challenger.<br /><br />Precondition: random-coin input_len is four after protocol parameters and the trusted setup.<br />Postcondition: random-coin input_len is six; output_len is zero.<br /><br />Inputs:  [...]<br />Outputs: [...]<br /> |
