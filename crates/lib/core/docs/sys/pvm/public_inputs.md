
## miden::core::sys::pvm::public_inputs
| Procedure | Description |
| ----------- | ------------- |
| stage_public_root | Stores the deferred root as the PVM's four base-field public values.<br /><br />The ACE READ layout represents each base value as a quadratic-extension element, so the root<br />is stored as `[D0, 0, D1, 0, D2, 0, D3, 0]` at the generated public-input boundary. Every cell<br />is overwritten, including the zero coordinates, so sequential verification cannot read stale<br />relation state.<br /><br />Inputs:  [D0, D1, D2, D3, ...]<br />Outputs: [...]<br /> |
| process_public_inputs | Observes the PVM statement and instance shape (step I of the verifier).<br /><br />This mirrors the lifted verifier's exact order:<br /><br />1. trusted preprocessed commitment;<br />2. default statement encoding `[4, D0, D1, D2, D3, 0, 0]`, where the final zeroes are<br />`max_aux_inputs` and `aux_inputs.len()`;<br />3. instance shape `[10, h0, ..., h9]` in `ChipletAir::all()` order.<br /><br />The resulting 22-felt stream performs two full-rate duplexes and leaves six felts buffered.<br />The generic verifier appends the four-felt main commitment and flushes before sampling, exactly<br />matching the Rust challenger. The four root values were staged by `stage_public_root`.<br /><br />Precondition: random-coin input_len is zero after protocol-parameter initialization.<br />Postcondition: random-coin input_len is six; output_len is zero.<br /><br />Inputs:  [...]<br />Outputs: [...]<br /> |
